# Architecture Decision Records

Architecture Decision Records capture consequential choices, alternatives, and consequences. A `Proposed` ADR guides discussion but does not authorize implementation. Only an explicitly `Accepted` ADR forms part of the approved architecture baseline.

## Lifecycle

1. **Proposed:** Under review; no implementation authorization.
2. **Accepted:** Approved and binding until superseded.
3. **Rejected:** Considered but not selected.
4. **Superseded:** Replaced by a later ADR.
5. **Deprecated:** No longer applicable but retained for history.

Changes to an accepted decision require a new ADR that links to and supersedes the previous record.
